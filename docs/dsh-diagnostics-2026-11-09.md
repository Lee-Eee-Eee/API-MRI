# DSH 测评排障记录

2026 年 11 月 9 日。用户反馈在 DSH 中一直无法完成测速、工具和指纹测评。本轮从已保存的失败记录追到宿主适配器，再验证完整调用链。

## 原因与修复

| 现象 | 原因 | 修复 |
| --- | --- | --- |
| 短指纹首题返回 422 | 探针发送 `usage: {include: true}`，API-MRI 适配器未接受该字段 | 严格校验该用量选项，在桥接层返回 DSH 自报用量 |
| 工具结果回填始终跳过 | 回填依赖“强制指定工具”成功，而 DSH 的 `ctx.llm` 没有该控制 | 自动选工具成功后也可进入回填；报告保留强制调用不支持 |
| 工具参数 JSON 不完整 | 推理与输出共用 128 token 上限，工具调用被截断 | 有明确 `off` 档位时关闭推理；DSH 服务测量默认 256 tokens；先识别截断再解析参数 |
| 多工具调用或流末尾补齐被误判 | 判分只接受一项工具，流转换遗漏后补 ID、名称或参数 | 校验并执行已声明的合成查表工具，补齐流末尾字段 |
| 失败只显示网络或模型调用异常 | SSE 出错后直接断流，原始失败分类丢失 | 返回固定安全错误分类，保留到证据与界面 |
| 推理用量显示为零 | 桥接层把未提供的分项补成零 | 未提供的计量保持未知 |

原始记录显示，11 月 9 日的两次流式测速均收到完整响应；同次工具请求出现适配器拒绝及输出截断。11 月 2 日的三次候选指纹请求均在桥接层被 `usage` 字段拒绝。私人历史记录留在用户数据目录。

## 可重复检查

[隔离全链脚本](../dsh-plugin/tests/host-model-e2e.mjs)运行真实已安装 DSH 与官方 pi-ai 适配器，上游使用回环地址的合成 SSE 服务。它覆盖 `/api/plan`、临时授权、`/api/runs`、原始证据下载和离线复算，断言复算不会再次调用上游。

```powershell
node dsh-plugin/tests/host-model-e2e.mjs --out docs/dsh-model-e2e-check.json
```

[机器可读结果](dsh-model-e2e-check.json)记录该隔离检查。它不使用真实供应商账户。真实调用结果另见上表。

验收已安装插件及便携程序时，另加 `--plugin-root <插件目录> --runtime <API-MRI.exe路径>`。此时参考探针从运行包读取，后端直接执行安装包。

DSH 的工具控制和推理控制依据[官方模型适配器说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/llm-deepseek/README.md)及本机安装的 `dsh-llm`、`dsh-llm-pi-ai`、`dsh-llm-deepseek` 实现核对。
