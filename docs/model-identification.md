# 单 API 模型候选识别

输入待测端点后，API-MRI 发送共同短探针，将回答分布与内置候选比较。请求里的模型别名只决定向接口请求什么，不参与排名。结果列出最近的候选、家族、JSD 距离和采样成本。

## 先运行一次

启动 `api-mri ui`，进入默认的“模型候选识别”。

1. 可以先选一个标签，点击“生成合成演示”。该流程在本机生成回答，无需 Key。
2. 真实采样填写 Base URL、接口接受的模型名和 Key，保留默认 32 次预算，点击“查看采样计划”。此按钮不发送模型请求。
3. 核对共同单元数、候选数、请求与输出预算，再开始。更改配置后须重新查看计划。
4. 完成后查看候选表、停止原因和供应商用量，下载 Markdown、JSON 与 JSONL。历史结果可重开；导入识别 JSONL 可离线复算。

每单元包含完整 system/user 提示，采 4 次；每次 `temperature=1`、`max_tokens=16`，请求关闭推理。开始新单元前预留完整的 4 次请求与 64 输出配额。不重试失败请求，也不为参数试探另花一次调用。API 不支持此协议时，保存失败并停止。

候选范围默认为全部 132 个标签。筛选家族可作探索，但全库校准门槛不适用于子集，结果会标为证据不足。输出配额是请求参数之和，输入和额外推理费用另计；供应商未返回的用量保留未知。

结果现在可以逐项展开：每道探针的实际回答次数、前三名参考分布、各探针对前两名距离差的贡献，以及每增加一个完整单元后的排序。正的贡献表示该题更接近当前首位，负值表示该题更接近第二位。再逐一删去一个探针重排，可以看到首位是否由某一题支撑。这些分析复用已采回答，额外 API 请求为零。

“删一探针后首位保持 7/8 次”描述本次排名的敏感性，不能读成 87.5% 的身份把握。参考分布、删除后的候选和作者记录的提供方随 JSON 导出。

## 命令行

复制 [identify.example.json](../examples/identify.example.json)，修改地址与模型别名。配置只写环境变量名，不写明文密钥：

```json
{
  "candidate": {
    "api_base": "https://your-service.example/v1",
    "model": "your-api-model-alias",
    "api_key_env": "API_MRI_KEY"
  },
  "budget": {"max_requests": 32, "max_output_tokens": 512},
  "timeout": 30,
  "api2d_no_cache": false
}
```

按[环境变量指南](user-guide.md#在命令行中提供密钥)提供 `API_MRI_KEY` 后运行：

```bash
api-mri identify-plan --config identify.json
api-mri identify --config identify.json --out runs/identify-01
api-mri identify-demo --out runs/identify-demo-01
api-mri identify-replay --records runs/identify-01/identification_records.jsonl --out runs/identify-replay-01
```

Windows 未激活虚拟环境时，使用 `.\.venv\Scripts\api-mri.exe`。每次使用新输出目录。请求数硬上限 32、累计输出配额硬上限 512；更小预算可能无法完成至少 3 个单元。

默认 `"stop_policy": "fixed"` 用完设置的完整单元预算。可选 `"stop_policy": "stable_shortlist"` 在至少完成 6 个单元后，检查连续两阶段是否首位相同且分别通过对应门槛；满足时提前结束候选检索，最多省去 8 次请求。历史留出集复算中，平均省去 3.11 次请求，同时出现了更多通过门槛的错选；[顺序停止验证](identification-stress.md)列出这项取舍。旧配置省略此字段时继续采用固定预算。

## 三种结果怎样读

| 结果 | 含义与后续动作 |
| --- | --- |
| 已得到库内候选 | 最近距离及前两名间隔通过本库离线门槛；检查前几名及具体服务承诺，继续取得版本和路由说明 |
| 库外模型或服务行为变化 | 回答超出同轮已知样本的距离范围；可能涉及新型号、配置或路径变化，记录本次条件 |
| 采样证据不足 | 单元未完成、候选过近、协议不符或校准不适用；查看停止原因和缺项 |

距离越小表示这组回答分布越近。报告不把它写成“模型身份概率”，`identity_decision` 始终保留 `abstained`。家族来自作者的 `family_guess`，家族距离取其中最近标签，只作归组展示。

遇到整段回答缓存、返回推理内容或推理用量、截断、空答、拒答及网络/格式错误，采样会停止；已发生的请求仍计入成本。API2D 用户可在采样设置中显式开启公开的 `x-api2d-no-cache: 1` 绕过头。工具不通过加随机字符串改变原探针。没有缓存标记，也不能据此证明服务没有缓存。

报告保存完整请求、响应、有限缓存响应头、用量、参考 SHA-256 和记录链。记录链用于发现改动、核对复算输入；持有文件者可以重新生成它，不能据此认证记录来自哪家服务。记录可能包含你设置的端点和模型别名，共享前检查内容。

## 数据和方法

参考来自 Bruckner 的 [One Token Is Enough 论文](https://arxiv.org/html/2607.10252v1)、[公开数据](https://zenodo.org/records/21278557)和[配置及归一化代码](https://zenodo.org/records/21278793)。10 类任务 × 4 种语言共 40 个共同单元。原采集在 2026 年 7 月 6—8 日，候选名称和提供方沿用作者记录。

重复编号 `rep % 3` 为 0、1、2 的记录分别作参考、校准、测试。固定种子移除 33 个完整模型标签：16 个只用于未知拒判门槛开发，17 个用于最终未知测试；部署库保留 132 个标签。提供方在每个作者标签内合并。因此测试具有记录留出，尚无跨日、跨提供方独立性。

首个单元按候选两两平均 JSD 除以 UTF-8 长度成本代理选择；后续在最近 12 个候选间选下一单元。每单元 4 条有效回答后，与全部候选计算平均 JSD。未满 4 条的单元不进入排名。默认按固定预算结束；实验性顺序停止采用上面列明的规则，单独复算其成本与错选情况。

## 保留测试

| 请求数 | 输出配额 | 库内 Top-1 | 库内 Top-3 | 已知样本通过门槛 | 通过者中正确 | 未知测试误放行 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 12 | 192 | 73/131 | 95/131 | 31/131 | 24/31 | 0/17 |
| 16 | 256 | 79/131 | 107/131 | 62/131 | 48/62 | 0/17 |
| 24 | 384 | 97/131 | 115/131 | 61/131 | 60/61 | 1/17 |
| 32 | 512 | 103/131 | 121/131 | 64/131 | 63/64 | 0/17 |

132 个库内标签中 1 个没有足够有效测试回答完成第三单元，分母为 131，缺失不计成功。32 请求下 Top-1 为 78.63%，Top-3 为 92.37%；保守门槛拒判 67 例，放行的 64 例中仍有 1 例错选。17 个未知测试零放行，对应误放行率 95% 单侧二项上界约 16.2%。小预算下通过者也存在较高错选，不能照搬 32 请求的结果。

首次只用已知分布的 95% 距离包络，32 请求放行了 16/17 个未知标签。当前门槛加入未知开发集和前两名间隔。这个失败基线说明，最近候选与实际身份之间还有明显距离。

固定种子 20261024 的一组随机题序在 32 请求下 Top-1 为 90/131，主动选题为 103/131；主动选题平均提示长度约 6183 UTF-8 字节，固定题序约 5704 字节。这一次比较不能证明总费用一定更低，后续同时测输入、输出、拒判和费用。完整指标与逐样本轨迹见 [离线计算记录](identification-offline.json)。

## 如何扩充与复现

“抓取参考库更新”目前更新的是 **KBF 指定模型对照库**。候选识别库使用另一套共同提示；仅抓取新型号名称不能产生其回答分布。新型号应按相同协议采集多次、记录提供方与时段，再留出校准和测试。

现有 KBF 26 包的完整请求批次没有跨包重合，不能直接拼入本库。它们继续用于“指定模型对照”；双端点的 Inspect/MET 流程也保留。

复现当前库时下载作者两个归档，核对 MD5：数据 `f2ce3fba3081f73e9908179fb2f061b6`，配置/代码 `d81de3b8ef5c0bca74fd7c2bdbb41a6b`，执行：

```bash
python -m relay_audit.identification_build --data-zip data.zip --code-zip code.zip --bank rebuilt/bank.json --evaluation rebuilt/evaluation.json
```

输入归档只作为数据读取，不执行归档中的代码；输出使用新路径。参考计数为 CC BY 4.0 派生数据，归一化规则据 MIT 代码独立移植，归属及许可见随包 [NOTICE](../src/relay_audit/data/identification/NOTICE)。

顺序停止、分提供方/日期和混合路由压力检查可由同一归档复现：

```bash
python -m relay_audit.identification_validation --data-zip data.zip --code-zip code.zip --out validation/stress.json
```

命令核对两个归档哈希、使用原有参考/校准/测试拆分，输出可逐项检查的配对记录。它不修改参考库或原始离线结果。
