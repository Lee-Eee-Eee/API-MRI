# 连接、流式响应与工具调用

填写一个兼容 Chat Completions 的 API 地址和模型别名，即可测量这条接入路径的响应情况。地址、模型、采样设置与单次结果一起保存，方便比较同一服务的不同时段、套餐或路由配置。

## 一次测量做什么

默认串行发送两次短流式请求，再检查四个工具环节：指定工具、自主选择工具、无需工具时直接回答、读取工具返回结果。最多六次请求，每次申请128 tokens，累计申请768 tokens。工具回读依赖第一次调用的名称和参数有效；未通过便跳过回读。可以只选速度或工具检查。

开始前的计划列出最坏调用数和输出配额。预算不足时按顺序停止，不会为了凑出结果增加请求。鉴权、限流、网络、超时或响应过大时停止后续采样；参数不兼容会保留原始拒绝结果。所有请求都不自动重试。

速度任务要求顺序输出1至40，每次带不同测量编号，减少整段回答缓存复用。它测量短输出、单客户端、并发1的工作负载。第一次请求可能建立连接，后续可能复用连接；比较时保留这个顺序。

## 时间和速度怎样读

| 字段 | 计算与含义 |
| --- | --- |
| 响应头延迟 | 从发出请求到收到HTTP响应头，包含网络、排队及服务端处理 |
| 首正文延迟 | 从发出请求到收到第一个非空正文事件；角色块、空块、推理内容分别处理 |
| 首推理延迟 | 首个非空推理事件的接收时间，保存在对应请求中 |
| 完整响应时间 | 从发出请求到流结束、出错或停止读取 |
| 返回用量／完整响应时间 | 供应商返回的`completion_tokens`除以完整响应秒数；可能包含推理tokens |
| 正文事件间隔 | 两次非空正文事件之间的接收时间，反映停顿和缓冲 |
| 字符／完整响应时间 | 保存正文的字符数除以完整响应秒数；单位始终是字符/s |

一块SSE响应可以包含多个tokens。标准接口不返回首块token数，因此工具保留精确正文解码速率为未知，不把事件数当成token数，也不把块间隔写成逐token延迟。供应商不返回有效`usage`时，token/s和用量保留未知，仍可查看正文、时间线和字符速率。

请求数、成功比例、中位数和p95均来自本次样本；p95使用线性插值。两三个样本适合发现明显故障，判断长期稳定性需要在多个时段重复采样。截断、只返回推理、未收到流终止标记、非流式返回和协议错误分别记录。接口报告生成错误或内容过滤时计为失败，不进入成功样本的速度汇总。成功比例按本次已发出的请求计算，鉴权或限流后的提前停止也会显示。

响应头中的缓存标记原样保存。CDN的`x-cache`与整段模型回答缓存的含义可能不同；返回token用量与交付速度也不直接表示新生成速度。

## 工具能力拆成四个观察

| 环节 | 合成任务 | 通过条件 |
| --- | --- | --- |
| 指定调用 | 强制调用`lookup_sample`读取样本MRI-17的温度 | 恰好一个函数调用，名称正确、参数JSON有效且符合固定字段和值 |
| 读取结果 | 本机返回温度、单位及本次随机回执 | 模型按要求复述三个字段，并且不发起额外调用 |
| 自主选择 | 同时提供样本查询和单位释义，询问样本的实测温度 | 选择样本查询工具，调用名称与参数正确 |
| 无需工具 | 仍提供工具，要求直接回答HELLO | 不调用工具，直接给出指定回答 |

单位释义工具说明“C代表什么”，不提供样本实测值。自主选择任务不在问题里指定函数名，用它作为干扰项检查模型能否选对工具。无需工具的控制任务也同时提供两个工具。

只有参数核对通过后，程序才在本机生成一条合成表结果。模型的工具名和参数不会变成文件访问、网络请求或系统命令。四项分别判分，指定调用通过不会自动给“自主选择”加分。这套小回路用于核对接入协议和简单工具行为；复杂Agent任务另建相应任务集。

## 兼容性与预算

高级设置可明确选择输出参数：

- `max_tokens`：默认兼容参数。
- `max_completion_tokens`：接口要求这一参数时选择；该参数可包含推理tokens。
- `stream_usage=false`：不发送`stream_options`，用于不接受这一扩展的网关。接口没有返回用量时不推算tokens。

工具按选定参数的值累计申请配额。配额是请求设置，账单还取决于输入、返回用量和服务商计费方式。采集记录保存供应商返回的输入、输出、总量及推理分项；缺失不补零。

示例配置：

```json
{
  "candidate": {
    "api_base": "https://api.example.com/v1",
    "model": "your-model-alias",
    "api_key_env": "API_MRI_KEY"
  },
  "checks": ["stream", "tools"],
  "samples": 2,
  "max_tokens": 128,
  "token_parameter": "max_tokens",
  "stream_usage": true,
  "timeout": 30,
  "budget": {"max_requests": 6, "max_output_tokens": 768}
}
```

## 留下可以复核的记录

输出目录包含计划、`service_records.jsonl`、JSON报告和Markdown报告。记录包括请求体、允许留存的响应头、原始JSON或SSE事件、相对时间、工具判分和用量；密钥不会写入请求记录。流中跨块回显的密钥也会遮蔽。

离线复算重新检查记录哈希、请求顺序和预算，从HTTP状态、终止标记及原始响应重算错误分类，从保存的事件复算正文、时间及用量，从原始工具响应重新判断参数与回读。任务停止原因须与末次请求和剩余预算相符。哈希用来发现文件变化；服务商是谁、是否实际运行某型号仍需其他证据。模型指纹、服务性能与工具结果并列保存，避免把响应慢、工具不支持或计量缺失混成模型身份判断。

合成演示走本地HTTP fixture，实际API请求数为零，界面显示的时间与响应为合成值。程序验证使用超时、鉴权、限流、SSE断流、推理、分块UTF-8、缺失用量、错误工具和篡改记录等离线情境，真实端点性能另行测量。
